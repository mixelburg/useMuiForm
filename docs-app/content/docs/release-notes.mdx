# Release Notes - v4.0.0

## 🎉 Major Release - Configuration System & Lazy Input Improvements

We're excited to announce **v4.0.0** of useMuiForm, featuring a comprehensive configuration system, improved lazy input validation, and better developer experience.

## ✨ New Features

### 🔧 Global Configuration System

You can now configure useMuiForm globally or per-form instance with deep merge support!

#### UseMuiFormConfigProvider

Wrap your app with the new configuration provider to set global defaults:

```tsx
import { UseMuiFormConfigProvider } from 'usemuiform'

<UseMuiFormConfigProvider config={{
  requiredFieldErrorMessage: "This field is required!",
  defaultOpts: {
    required: false,  // All fields optional by default
    lazy: true        // All fields use lazy/uncontrolled mode by default
  }
}}>
  <App />
</UseMuiFormConfigProvider>
```

#### Per-Form Configuration

Override context configuration at the hook level:

```tsx
const form = useMuiForm({
  defaultValues: { email: '', name: '' },
  config: {
    requiredFieldErrorMessage: "Please fill this field",
    defaultOpts: {
      required: true,
      lazy: false
    }
  }
})
```

#### Configuration Priority Chain

Configurations are deep-merged in the following order (lowest to highest priority):

1. **Default config** (hardcoded: `required: true`, `lazy: false`)
2. **Context config** (from `UseMuiFormConfigProvider`)
3. **Hook config** (passed to `useMuiForm`)
4. **Field config** (passed to `register()`)

This means you can set global defaults and override them where needed!

### 🎯 Default Options System

New `defaultOpts` configuration key lets you set default behavior for all fields:

- **`defaultOpts.required`**: Sets whether fields are required by default (default: `true`)
- **`defaultOpts.lazy`**: Sets whether fields use lazy/uncontrolled mode by default (default: `false`)

```tsx
// Make all fields optional and lazy by default
const form = useMuiForm({
  defaultValues: { ... },
  config: {
    defaultOpts: {
      required: false,
      lazy: true
    }
  }
})

// Individual fields can still override
<TextField {...register('email', { required: true, lazy: false })} />
```

### ⚡ Improved Lazy Input Validation

**Breaking Change**: Lazy inputs now validate immediately on blur, regardless of whether `forceValidate()` has been called.

#### Before v4.0.0:

```tsx
// Lazy inputs only validated after forceValidate() was called
<TextField {...register('email', { lazy: true, validate: emailValidator })} />
// User blurs field → no validation until form submit
```

#### After v4.0.0:

```tsx
// Lazy inputs validate on blur automatically
<TextField {...register('email', { lazy: true, validate: emailValidator })} />
// User blurs field → validation runs immediately, errors shown
```

This provides better UX by giving immediate feedback to users without sacrificing the performance benefits of uncontrolled inputs.

## 🔨 Internal Improvements

### Extracted Validation Logic

- Created reusable `validateField()` function
- Eliminates code duplication between `validate()` and `handleBlur()`
- Ensures consistent validation behavior across the codebase
- Easier to maintain and test

### Deep Merge Support

- Added `deepmerge` dependency for sophisticated config merging
- Prevents config overwrites, allows selective overrides
- More flexible and intuitive configuration experience

## 📚 Updated API

### useMuiForm(options?)

#### Parameters

- **`options`** (optional):
  - `defaultValues?: State` - Initial form values
  - **`config?: UseMuiFormConfig`** - ⭐ **NEW**: Per-form configuration

#### UseMuiFormConfig Interface

```typescript
interface UseMuiFormConfig {
  requiredFieldErrorMessage?: string
  defaultOpts?: {
    required?: boolean  // Default: true
    lazy?: boolean      // Default: false
  }
}
```

### register(name, options?)

Field-level options now inherit from config defaults:

```typescript
register(name, {
  required?: boolean,      // Inherits from config.defaultOpts.required
  lazy?: boolean,          // Inherits from config.defaultOpts.lazy
  validate?: (value, state) => true | string,
  format?: (value) => any,
  disabled?: boolean,
  helperText?: string
})
```

## 📦 New Dependencies

- **`deepmerge`** - For intelligent configuration merging

## 🔄 Migration Guide

### For Most Users

No breaking changes if you don't use lazy inputs. Upgrade safely! 🎉

### If You Use Lazy Inputs

Lazy inputs now validate on blur. This is generally desirable, but if you need the old behavior:

**Option 1**: Remove `lazy` flag and use controlled inputs

```tsx
// Before
<TextField {...register('email', { lazy: true })} />

// After (for old behavior)
<TextField {...register('email')} />
```

**Option 2**: Handle validation state manually if needed

```tsx
// You still have full control over when to show errors
const { errors, touched } = useMuiForm(...)
// Custom logic here
```
